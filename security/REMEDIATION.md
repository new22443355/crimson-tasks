# Исправления после red-team проверки

Дата проверки: 12 ноября 2026 года, Europe/Moscow.

[RED_TEAM_REPORT.md](RED_TEAM_REPORT.md) — неизменённый автоматически сформированный отчёт о состоянии **до** исправлений. Он сохраняет исходные доказательства двух проблем низкой серьёзности. Этот документ описывает последующие изменения и проверки; он не заменяет исходный отчёт.

## Исправленные проблемы

| Проблема | Изменение | Результат повторной проверки |
| --- | --- | --- |
| Клиент выбирал общий бюджет авторизации через `CF-Connecting-IP` | Общий ключ экземпляра задаётся сервером; заголовки клиента не участвуют в выборе ключа | Три запроса с разными заголовками при исчерпанном бюджете получили 429 |
| Отклонённые запросы с новыми логинами оставляли постоянные ключи | Общий лимит проверяется до создания пользовательского ключа; удаляются до 100 устаревших записей за запрос | После трёх отклонённых запросов новых пользовательских ключей — 0; устаревшая тестовая запись удалена |

Счётчики насыщаются на `limit + 1`, чтобы повторные запросы не приводили к переполнению integer. Индивидуальный лимит 12 попыток за 15 минут сохраняется; общий лимит экземпляра — 60. Очистка использует индекс `auth_rate_window_idx` и повторную проверку срока перед удалением. Независимое ревью исправлений не выявило блокирующих регрессий.

Регрессионный тест: `npm run test:security`. Он выполняется внутри работающего контейнера приложения, создаёт только временные записи ограничителя и восстанавливает исходную общую запись. Используйте отдельный тестовый экземпляр без одновременных попыток входа.

Для существующей БД добавлен только индекс. Перед применением создана локальная резервная копия `pg_dump -Fc`, проверенная через `pg_restore --list`. Полное восстановление этой копии отдельно не выполнялось. Новая установка получает индекс из `db/schema.sql` автоматически.

## Зависимости

Дополнительная проверка `npm audit` выполнена после завершения исходного аудита. Она сообщила об известных уязвимостях в четырёх пакетах: `next`, `sharp`, `baseline-browser-mapping`, `source-map-js`. Это результаты сопоставления версий с advisory-базой; эксплуатация этих уязвимостей в приложении не доказывалась.

Обновлены Next.js до 16.4.6, sharp до 0.35.5, baseline-browser-mapping до 2.11.36 и source-map-js до 1.2.2. Обновлён lockfile. Для Next.js дополнительно сверены первичные уведомления разработчика об [Image Optimization](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw) и [`use cache`](https://github.com/vercel/next.js/security/advisories/GHSA-673q-mjm6-r5xr).

Повторный `npm audit --json`: **0 известных уязвимостей**, включая dev-зависимости. Это состояние базы advisories на дату проверки, а не гарантия отсутствия неизвестных уязвимостей.

## Проверки исправленной версии

- `npm run typecheck` — успешно.
- `npm run local:up` — Docker-сборка Next.js 16.4.6 успешна, приложение и PostgreSQL healthy.
- `npm run test:integration` — 11/11 тестов: регистрация, сессии, CSRF, валидация, CRUD, изоляция пользователей, конкурентное редактирование и аудит.
- `npm run test:security` — оба воспроизведения больше не срабатывают; индивидуальный лимит и разрешённая проверка пароля работают.
- Playwright / Chrome 157 — регистрация, создание, редактирование, выполнение, обновление страницы, удаление, история и выход проверены через интерфейс. XSS-строка с `img/onerror` остаётся текстом: DOM-элемент не создаётся, обработчик не выполняется, в том числе после обновления и в истории. Ошибок JavaScript и внешних запросов нет. Просмотрены desktop 1440 px и mobile 390 px; горизонтального переполнения нет.
- Docker публикует веб-порт только на `127.0.0.1:3000`; порт PostgreSQL на хост не опубликован.
- Остановка и повторный запуск Docker ранее проверены: задача, отметка выполнения, сессия и аудит сохранились.
- Проверены 142 blob-объекта текущей Git-истории на совпадения с действующими локальными паролями/токенами и блоки приватных ключей: совпадений нет. Это целевая проверка, а не доказательство отсутствия любых исторических секретов.

## Границы проверки

Проверялся локальный Docker-вариант приложения. Windows ACL, альтернативные ручные конфигурации БД и уязвимости системных пакетов Docker-образов отдельно не проверялись. Нагрузочное заполнение диска и внешние атаки не выполнялись. Администратор компьютера/Docker/БД остаётся доверенной стороной. Измеренный расход токенов исходного сканирования недоступен.

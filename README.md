# Дневник дел

Личный список задач в бордово-кремовом университетском стиле. Работает локально: Next.js, Node.js и PostgreSQL. Аккаунты Sites, ChatGPT и Neon для запуска не нужны. Проект не связан с Гарвардским университетом.

## Быстрый запуск

Нужны Git, Node.js 22.13+ (с npm) и запущенный Docker Desktop с Docker Compose v2. На Linux подходит Docker Engine с плагином Compose v2. Первый запуск требует интернет для загрузки контейнеров и зависимостей; затем приложение работает на вашем компьютере.

```sh
git clone https://github.com/new22443355/crimson-tasks.git
cd crimson-tasks
npm run local:up
```

Репозиторий приватный: владелец должен добавить получателя в **Settings → Collaborators**, а получатель — принять приглашение и авторизоваться в GitHub. Одна ссылка без предоставленного доступа не позволяет клонировать код.

Откройте **http://127.0.0.1:3000** и нажмите «Создать аккаунт». Новый логин — 4–32 латинских символа, цифры, `_`, `.` или `-`; пароль — 4–128 символов. Существующие трёхсимвольные логины продолжают работать. Заранее созданного аккаунта сайта нет.

Команда сама создаёт локальный `.env.docker` со случайными паролями, собирает приложение, запускает PostgreSQL, применяет схему и проверяет готовность сервисов. Устанавливать npm-зависимости или PostgreSQL на компьютер отдельно не требуется.

## Что умеет приложение

- Регистрация, вход и выход по логину и паролю.
- Настройки аккаунта: смена логина и пароля с проверкой текущего пароля. Задачи сохраняют прежнего владельца; после смены пароля остальные сеансы завершаются.
- Личные задачи: добавление, редактирование, выполнение, отмена, возврат в работу и удаление.
- Заметки, календарь, приоритеты и прогресс в едином оформлении.
- Фильтры по статусу, приоритету, дате создания и сроку; поиск по словам в названии и заметке.
- Поисковый запрос сохраняется для аккаунта в текущем браузере. Найденная задача остаётся видимой после изменения статуса до очистки запроса.
- Сохранение данных после обновления страницы и перезапуска контейнеров.
- Журнал регистрации, входов, выходов и изменений задач с фильтрами по действию и датам; события сохраняются после удаления задачи.

## Остановка и повторный запуск

```sh
npm run local:down
npm run local:up
```

Остановка сохраняет данные в Docker volume `crimson-tasks-local_postgres_data`. Повторный запуск использует прежние пароли и БД. Не удаляйте `.env.docker`, пока нужна существующая БД; храните резервную копию этого файла вне Git. Команды запуска не сбрасывают данные и не заменяют пароли.

После обновления кода снова выполните `npm run local:up`. Перед новыми миграциями команда создаёт резервную копию PostgreSQL в `.local-backups/`, проверяет читаемость архива и применяет изменения в транзакции. Каталог копий исключён из Git и Docker build context; он содержит ваши данные. Применённые SQL-миграции не изменяются и повторно не выполняются.

Статус и журналы:

```sh
npm run local:status
npm run local:logs
```

Если порт 3000 занят, остановите другое приложение на этом порту перед запуском.

## Где находятся данные и доступы

БД называется `crimson_tasks`, ограниченная роль приложения — `test`. Случайные пароли администратора и этой роли генерируются в `.env.docker`, который исключён из Git и Docker build context. Docker передаёт их соответствующим контейнерам через переменные окружения. Роль БД `test` и аккаунт сайта — разные сущности.

Приложение доступно на `127.0.0.1:3000`. Порт PostgreSQL не опубликован на хост. Данные каждого клона находятся у получателя на его компьютере, а не в репозитории. Секреты, пользовательские задачи и содержимое БД в GitHub не загружаются.

## Разработка и проверки

Код интерфейса находится в `app/page.tsx` и `app/globals.css`, серверная логика — в `lib/server/`, схема и права PostgreSQL — в `db/`. Docker собирает Next.js в режиме `standalone`.

Для проверки исходников:

```sh
npm ci
npm run typecheck
npm run build
```

При запущенном локальном приложении:

```sh
npm run test:integration
npm run test:filters
```

Интеграционные тесты создают отдельные аккаунты с уникальными именами и тестовые события аудита; они не удаляют пользовательские данные. Для проверки используйте отдельный локальный экземпляр, если в текущей БД хранятся важные задачи. Тесты проверяют жизненный цикл задач, сохранение, изоляцию пользователей, CSRF, валидацию, конкурентное редактирование и аудит.

`npm run test:security` проверяет ограничитель входа в работающем Docker-экземпляре: подмена заголовков не даёт новый бюджет попыток, отклонённые запросы не добавляют ключи, устаревшие записи удаляются. Тест временно меняет общий счётчик и восстанавливает его; запускайте в отдельном тестовом экземпляре без одновременного входа других пользователей.

Для браузерной регрессии установите зависимости (`npm ci`) и Chromium (`npx playwright install chromium`), затем выполните `npm run test:browser` при работающем приложении. Можно использовать установленный Chrome: `PLAYWRIGHT_CHANNEL=chrome npm run test:browser`. Проверка создаёт собственный тестовый аккаунт; снимки экрана сохраняются во временный каталог вне репозитория.

Исходный [отчёт red-team](security/RED_TEAM_REPORT.md) описывает состояние до первоначальных исправлений. [Исправления и повторные проверки](security/REMEDIATION.md) относятся к версии `ba9de43`; последующие функциональные изменения проверяются отдельно.

Для разработки без контейнера приложения нужен собственный PostgreSQL: заполните `DATABASE_URL` и отдельный `MIGRATION_DATABASE_URL` владельца БД в игнорируемом `.env.local`, сохраните резервную копию и выполните `npm run db:migrate`. Примените `db/runtime-grants.sql` от владельца БД, затем запустите `npm run dev`. Docker-инициализация выполняется только на пустом volume; обновления существующей Docker-БД применяет команда `local:up`.

Пароли пользователей хешируются с солью; токены сессий сохраняются в виде хешей. Сервер проверяет владельца задачи. Изменение задачи и аудит записываются атомарно; роль приложения не может изменять или очищать журнал. Администратор PostgreSQL сохраняет административный доступ к БД.

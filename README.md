# Дневник дел

Личный список задач в университетском стиле: бордовый, кремовый, строгая типографика. Интерфейс на русском языке. Проект не связан с Гарвардским университетом.

## Возможности

- Регистрация и вход по логину и паролю.
- Создание, редактирование, выполнение, возврат в работу и удаление своих задач.
- Описание, срок, приоритет, поиск и фильтры.
- Хранение пользователей, сессий, задач и истории в PostgreSQL.
- Журнал действий с сохранением событий после удаления задачи.
- Адаптивный интерфейс для телефона и компьютера.

## Устройство

React / Vinext работает как Cloudflare Worker на Sites. В опубликованном приложении PostgreSQL подключается через HTTP-драйвер Neon. Для локальной разработки используется PostgreSQL и отдельный HTTP-мост на loopback; он не предназначен для публикации в интернет.

`app/` — интерфейс и API-маршрут; `lib/server/` — серверная логика; `db/schema.sql` — схема; `tests/api.integration.mjs` — проверки на реальной БД.

## Локальный запуск

Требуются Node.js 22.13+ и PostgreSQL. Установите зависимости командой `npm ci`.

Создайте отдельную БД и runtime-роль `test` со случайным паролем. Миграции выполняет владелец БД; роль приложения не должна иметь права superuser, создания БД или ролей.

Скопируйте `.env.example` в `.env.local`, а `.dev.vars.example` в `.dev.vars`. Заполните соединение и одинаковый случайный токен моста в обоих локальных файлах. Ограничьте права файлов до `0600`. Реальные секреты в Git не сохраняются.

Для применения схемы задайте `MIGRATION_DATABASE_URL` владельца БД и выполните `npm run db:migrate`. Затем выдайте runtime-роли права из `db/runtime-grants.sql` от владельца БД.

В отдельных терминалах запустите:

```sh
npm run db:bridge
npm run dev
```

Откройте Local URL, выведенный Vite. Создайте аккаунт: логин 3–32 символа, пароль 12–128 символов. Роль БД `test` и аккаунт сайта — разные сущности.

## Проверки

При работающем локальном приложении:

```sh
npm run typecheck
TEST_BASE_URL=http://localhost:5173 npm run test:integration
npm run build
```

Интеграционные тесты создают уникальные тестовые аккаунты и события. Используйте отдельную тестовую БД, если в среде есть пользовательские данные. Тестовые записи аудита не удаляются автоматически.

## Sites и PostgreSQL

Идентификатор Sites хранится в `.openai/hosting.json`. Настройки и сборка сохраняют интеграцию `sites()`.

1. Создайте PostgreSQL в Neon и примените схему от владельца БД.
2. Создайте ограниченную роль `test`, выдайте права из `db/runtime-grants.sql`.
3. Установите её строку подключения как secret `DATABASE_URL` в runtime-настройках Sites.
4. Сохраните и опубликуйте новую версию штатным процессом Sites.

Не задавайте локальный HTTP-мост как production-соединение. Sites сохраняет собственный внешний контроль доступа; регистрация внутри приложения не отменяет ограничения приватного Sites. Открывать доступ другим посетителям следует отдельно и явно.

## Защита данных

Пароли хешируются с индивидуальной солью; токены сессий хранятся в БД только в виде хеша. Cookie HttpOnly, SameSite=Lax, с Secure на HTTPS. Сервер проверяет владельца каждой задачи и ограничивает журнал текущим пользователем. Изменение задачи и аудит записываются одной SQL-операцией. Роль приложения не имеет UPDATE/DELETE/TRUNCATE для аудита; триггер дополнительно запрещает изменения журнала. Владелец БД с административными правами технически может изменить схему — это не внешнее неизменяемое хранилище.

Секреты доступа и локальные данные не включены в репозиторий. При эксплуатации отдельно организуйте резервное копирование PostgreSQL.
